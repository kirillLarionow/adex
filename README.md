# adex

Мини ad exchange на Go. Принимает аукционный запрос, фильтрует DSP-партнёров по условиям претаргетинга и параллельно отправляет им bid-запросы.

---

## Как запустить

Нужен Go 1.27+.

**1. Запустить мок DSP-серверы** (в отдельном терминале):

```bash
go run ./cmd/mockdsp
```

Поднимет три сервера: порты 9001, 9002, 9003. Сервер на 9003 отвечает с задержкой 500ms — для проверки таймаута.

**2. Запустить сам сервис** (в другом терминале):

```bash
go run ./cmd/adex
```

Сервис доступен на `http://localhost:8080`. Остановка — `Ctrl+C`: сервис перестаёт принимать новые запросы и дожидается завершения текущих.

## Настройки

Все настройки задаются переменными окружения и необязательны.

**Аукцион**

| Переменная | По умолчанию | Описание |
|---|---|---|
| `AUCTION_TIMEOUT` | `200ms` | Время на весь аукцион |
| `MAX_CONCURRENCY` | `50` | Максимум одновременных запросов к DSP |
| `PARTNERS_PATH` | `partners.json` | Путь к файлу партнёров |

**HTTP-сервер**

| Переменная | По умолчанию | Описание |
|---|---|---|
| `ADDR` | `:8080` | Адрес сервера |
| `READ_TIMEOUT` | `5s` | Время на чтение запроса |
| `WRITE_TIMEOUT` | `10s` | Время на обработку и отправку ответа |
| `IDLE_TIMEOUT` | `60s` | Время жизни простаивающего keep-alive соединения |
| `MAX_BODY_BYTES` | `1048576` | Максимальный размер тела запроса (1 МБ) |

**DSP-клиент**

| Переменная | По умолчанию | Описание |
|---|---|---|
| `DSP_TIMEOUT` | `3s` | Жёсткий таймаут одного запроса к DSP |
| `DSP_MAX_IDLE_CONNS` | `100` | Свободных соединений в пуле всего |
| `DSP_MAX_IDLE_CONNS_PER_HOST` | `20` | Свободных соединений в пуле на одну DSP |

Пример:

```bash
AUCTION_TIMEOUT=300ms MAX_CONCURRENCY=100 go run ./cmd/adex
```

Длительности задаются в формате Go: `200ms`, `3s`, `1m`. Все числовые значения должны быть больше 0. При невалидном значении сервис не запускается и пишет, какая переменная неверна.

## API

### `POST /auction`

Принимает аукционный запрос, фильтрует партнёров, рассылает запрос подходящим и возвращает итог.

Ошибки:
- `405` — метод не POST
- `415` — `Content-Type` не `application/json` (вариант с `charset` принимается)
- `413` — тело запроса больше `MAX_BODY_BYTES`
- `400` — невалидный JSON, неизвестные поля, не заполнены `request_id` / `country`, `device_type` не из `mobile`, `desktop`, `tv`, отрицательный `bid_floor`

### `GET /health`

Возвращает `200 OK`. Используется для проверки, что сервис жив.

## Пример curl-запроса

Запрос, на котором видна фильтрация:

```bash
curl -X POST http://localhost:8080/auction \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "req-1",
    "country": "RU",
    "device_type": "mobile",
    "bid_floor": 1.5,
    "categories": ["news", "sport"]
  }'
```

Пример ответа:

```json
{
  "request_id": "req-1",
  "matched_dsps": ["DSP Alpha", "DSP Beta"],
  "sent": 2,
  "succeeded": 1,
  "duration_ms": 201
}
```

Что произошло:
- DSP Gamma отфильтрована — категория `news` у неё заблокирована
- DSP Delta отфильтрована — `is_enabled: false`
- DSP Alpha прошла фильтрацию, но не ответила за 200ms (таймаут)
- DSP Beta прошла фильтрацию и ответила успешно

Логи сервиса покажут причину отклонения каждого партнёра.

## Партнёры

Партнёры хранятся в файле `partners.json` в корне проекта (путь меняется через `PARTNERS_PATH`). Файл читается при старте, после изменения сервис нужно перезапустить.

Чтобы добавить нового партнёра — добавить объект в массив:

```json
{
  "uuid": "unique-id",
  "name": "DSP New",
  "endpoint": "http://localhost:9004/bid",
  "is_enabled": true,
  "countries": ["RU", "US"],
  "device_types": ["mobile", "desktop"],
  "min_bid_floor": 1.0,
  "blocked_categories": ["adult"]
}
```

Правила фильтрации:
- `is_enabled: false` — партнёр полностью отключён
- `countries` — пустой массив означает «любая страна»
- `device_types` — пустой массив означает «любой девайс»
- `min_bid_floor` — партнёр не берёт запросы ниже этой ставки
- `blocked_categories` — если запрос содержит хоть одну из этих категорий — партнёр пропускается

## Как устроен аукцион

1. Хендлер проверяет запрос (метод, `Content-Type`, размер, JSON, обязательные поля).
2. Сервис прогоняет каждого партнёра через претаргетинг и отбирает подходящих.
3. Подходящим DSP запросы отправляются параллельно, но не больше `MAX_CONCURRENCY` одновременно.
4. На весь аукцион даётся `AUCTION_TIMEOUT`. Кто не ответил вовремя, не засчитывается; запросы, ещё ждущие очереди, не отправляются.
5. В ответе: кому отправили, сколько ответили успешно и сколько длился аукцион.

Соединения к DSP переиспользуются через пул, тело ответа дочитывается, чтобы соединение возвращалось в пул.

## Структура проекта

```
cmd/
  adex/        точка входа сервиса
  mockdsp/     мок DSP-серверов для локальной проверки
internal/
  config/        чтение настроек из переменных окружения
  domain/        общие типы
  partner/       загрузка партнёров из JSON
  pretargeting/  правила фильтрации партнёра
  auction/       сервис аукциона, параллельная рассылка
  dsp/           HTTP-клиент к DSP
  httpapi/       HTTP-хендлер и валидация запроса
```

## Тесты

```bash
go test ./... -race
```

Покрыто:
- **претаргетинг** — все правила фильтрации;
- **HTTP-хендлер** — метод, `Content-Type`, размер тела, невалидный JSON, неизвестные поля, валидация полей;
- **DSP-клиент** — успешный ответ, ответ не 200, отмена запроса по контексту;
- **сервис аукциона** — отправка только подходящим партнёрам, подсчёт успешных, таймаут медленного партнёра, ограничение конкурентности.
